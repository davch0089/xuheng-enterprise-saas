# 采购管理流程

采购模块实现从采购订单到供应商付款的 Purchase-to-Pay 闭环，库存数量和成本继续由 `StockPostingEngine` 与 `InventoryCostEngine` 统一维护。

## 业务流程

```text
采购订单草稿
  └─审核 → 可分批收货
       └─采购收货审核 → PURCHASE_IN 库存与移动平均成本过账
                         → 累计订单收货数量
                         → 生成供应商应付开放项

采购退货草稿（引用已审核采购收货）
  └─审核 → PURCHASE_RETURN 库存过账
          → 累计原收货退货数量
          → 冲减原供应商应付

采购付款草稿
  └─审核 → 指定应付核销，或按到期日 FIFO 自动核销
```

## 关键规则

- 采购订单审核不修改库存和应付，只进入可收货状态。
- 采购收货允许引用订单分批履约，也允许无订单直接采购收货。
- 并发审核收货时锁定订单行，禁止累计收货超过订单数量。
- 库存成本使用未税采购金额；供应商应付使用价税合计。
- 采购退货必须引用原收货行，不能超过可退数量；批次必须与原收货批次一致。
- 已付款的金额不能直接退货形成负应付，必须先撤销对应付款；供应商预付款仍可以通过未分配付款金额表达。
- 应付余额、开放项目和流水不可直接修改，业务更正必须倒序反审核。
- 已冲销单据重新审核会增加 `posting_version`，库存、成本和应付均使用新幂等版本。

## 倒序冲销

存在下游业务时，上游反审核会被拒绝。标准撤销顺序为：

```text
付款 → 采购退货 → 采购收货 → 采购订单
```

每一步均位于同一数据库事务中，任意库存、成本、订单进度或应付校验失败会整体回滚。

## HTTP 接口

- `/erp/purchase/orders`：采购订单增删改查、审核、反审核。
- `/erp/purchase/receipts`：采购收货增删改查、审核、反审核。
- `/erp/purchase/returns`：采购退货增删改查、审核、反审核。
- `/erp/purchase/payables`：供应商应付开放项。
- `/erp/purchase/payments`：付款增删改查、审核、反审核。
- `/erp/purchase/source-orders`：仍有未收数量的采购订单。
- `/erp/purchase/source-receipts`：仍有可退数量的采购收货单。
